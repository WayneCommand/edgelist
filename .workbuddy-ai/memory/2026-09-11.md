### 两个真 bug（都是阶段五顺带发现/修掉的）

1. **`location.pathname` 保留百分号转义**。Cloudflare 静态资源对导航请求把
   `/@login` 307 到 `/%40login`，`routeFor("/%40login")` 原先匹配不上，会掉进文件页；
   更严重的是含空格/中文的目录名会带着 `%20`/`%E4%B8%AD...` 直接发给 `fs/list`。
   修法：`routeFor` 先 `decodeURIComponent`（`try/catch`，非法转义按原样返回）。
   react-router 自己的 `matchRoutes` 会解码，所以路由匹配本身没问题，坏的是我们手写的
   `routeFor` / `filesPathFor`。
2. **`edgelist-auth-expired` 自定义事件**是多余的：`api()` 现在直接
   `clearAuthToken()`，store 通知 React 重渲染，`RequireAuth` 随即跳登录。
   `useAuth` 用 `useSyncExternalStore` + `sessionStorage` 镜像。

### 关键设计决定

- **偏好值一律存成短字符串**（`view-mode` = `list|grid`，`sort:<path>` = `name:asc`）。
  原语才能安全进依赖数组；每次 render 新解析出的对象会让 `useCallback` 换身份、
  effect 无限重跑。排序键用 **URL 路径**（`initialPath`）而不是 `path` state，
  否则导航后会因为 key 变化多取一次数据。
- **拆开两个 effect**：一个只依赖 `initialPath` 负责清空搜索框，另一个依赖
  `[initialPath, load]` 负责取数。合成一个的话改排序会把用户正在输入的关键词清掉。
- **排序是服务端的**（`fsList` 收 `order_by`/`order_direction`），前端不本地重排
  ——分页之后本地排只会排乱当前这一页。搜索态下表头不可排序（传 `sort={undefined}`）。
- **复制/移动前端也要挡一道**：`mountPathFor` 取源/目标挂载点（最长前缀，按 `/`
  边界匹配），不同就禁用按钮并提示，文案与后端 `fs-transfer.ts` 里的中文完全一致。
- 上传 input 在 `FileToolbar` 内部，选完立刻 `event.target.value = ""`，否则连续
  选同一个文件不会再触发 `change`。
- 测试策略：**不引入 jsdom / Testing Library**，用 `react-dom/server` 的
  `renderToStaticMarkup` 做渲染冒烟（零新依赖）。`vitest.config.ts` 的 `include`
  已加 `src/**/*.test.tsx`。

### 关键决策（下次别推翻）

- **`readEntries` 必须循环到空数组**：Chrome 单次最多 100 项，只读一次会静默
  丢条目。`readEntries` 不允许并发，所以要在回调里再发起下一次。
- 文件保留**相对路径** `{ file, path }`，不把路径拼进 `file.name`（OpenList
  那样做会让报错信息里的文件名变成整条路径）。
- **目录创建不用 `create_parent`**：该标志向上递归，而 S3 的 `mkdir` 会写一个
  0 字节目录标记对象 → 会从挂载根一路写上去，在用户桶里留垃圾。改为按深度排序
  逐个建，只碰上传目录以下。
- **必须 mkdir**：`fsPut` 直接透传适配器，S3 的 key 天然扁平不需要目录，但
  **WebDAV 的 `write` 是裸 PUT**，父集合不存在就失败；本机 `/jianguoyun`、
  `/jianguoyun-backup` 正是 webdav。
- mkdir 失败**有意吞掉**：重复拖同一目录时「已存在」是常态，紧随其后的 PUT 才是
  权威判据。避免在客户端字符串匹配各家驱动的错误文案。
- `DropZone` 用**计数器**而非布尔值驱动浮层（`dragenter`/`dragleave` 会随指针
  经过子元素反复触发）；浮层 `pointer-events-none`，否则自己制造 `dragleave`。
  另挂 window 级 `dragover`/`drop` 拦截，防止落在区域外时浏览器导航走掉。

### 复用价值最高的：怎么安全验收「写」流程

6.8 是写操作，不能像前几步那样只走只读路径。做法是**在浏览器侧用
`page.route` 拦截写端点**（`**/api/fs/mkdir`、`**/api/fs/put`、`**/api/fs/form`），
记录请求后用 `route.fulfill` 回一个 `{code:200,message:"",data:null}`——请求
根本不出进程，却能把整条客户端流水线（拖放 → 递归 → 建目录顺序 → PUT 头）验穿。
跑完再用真实接口列一次目录，确认条目数与验收前一致、无残留。拦截时**故意加
~80ms 延迟**，否则本地回包太快，`Uploading n/m` 这类中间态根本观察不到。

### 两个坑

- 同一文件的两处 `Edit` 放在同一条消息里并发执行，**只有一处落地**
  （`FilesPage.tsx` 的导入丢失 → `TS2304`）。同文件多处编辑必须串行。
- 目录选择器的 `webkitRelativePath` **包含被选中目录自身的名字**
  （选 `edgelist-pick` → `edgelist-pick/docs/a.md`）。第一版断言漏了这一层，
  是断言错了。`setInputFiles(<目录>)` 能真实复现这个语义，很适合验收。
