### 两个真 bug（都是阶段五顺带发现/修掉的）

1. **`location.pathname` 保留百分号转义**。Cloudflare 静态资源对导航请求把
   `/@login` 307 到 `/%40login`，`routeFor("/%40login")` 原先匹配不上，会掉进文件页；
   更严重的是含空格/中文的目录名会带着 `%20`/`%E4%B8%AD...` 直接发给 `fs/list`。
   修法：`routeFor` 先 `decodeURIComponent`（`try/catch`，非法转义按原样返回）。
   react-router 自己的 `matchRoutes` 会解码，所以路由匹配本身没问题，坏的是我们手写的
   `routeFor` / `filesPathFor`。
2. **`edgelist-auth-expired` 自定义事件**是多余的：`api()` 现在直接
   `clearAuthToken()`，store 通知 React 重渲染，`RequireAuth` 随即跳登录。
   `useAuth` 用 `useSyncExternalStore` + `sessionStorage` 镜像。

### 环境备忘（重要，比昨天更完整）

- 本机 **没有** `pnpm`。可用 `corepack pnpm`（先 `corepack prepare pnpm@11 --activate`，
  11.26.0 与 lockfile/store v11 匹配；pnpm 9 会报 store v3 不匹配）。
- **但 `pnpm exec` / `pnpm run` 会触发 `runDepsStatusCheck` → 自动跑 `pnpm install`**，
  而 install 在沙箱里必然失败（broker 拒绝在 `node_modules` 建/覆盖 symlink，
  报 `CODEBUDDY_BROKER_DENY` 或 `Brokered host link requires an available runtime file rule`）。
  → 结论：**直接用 `./node_modules/.bin/<tool>`**（tsc / eslint / vitest / vite / wrangler），
  prettier 用 `node node_modules/prettier/bin/prettier.cjs`。
- 新装依赖时的固定套路：先 `rm -f /Users/zero/Library/pnpm/store/v11/projects/<hash>`
  （指向本项目的 symlink，`registerProject` 会 EEXIST），再
  `corepack pnpm add -wD <pkg>`（要 `dangerouslyDisableSandbox`）。若最后卡在
  `symlinkHoistedDependency`，就手动补：
  `ln -s .pnpm/<pkg>@<ver>/node_modules/<pkg> node_modules/<pkg>` 和
  `ln -s ../<pkg>/bin/<bin> node_modules/.bin/<bin>`，再
  `corepack pnpm install --lockfile-only` 更新 lockfile。
- 长命令（tsc / eslint）偶尔 SIGTERM(137)，重跑一次即可。
