### 值得记住的技术判断

1. **列表里没有 MIME**：S3 与 WebDAV 都把 `Content-Type` 留空，worker 只透传。要按 MIME 分派就得先下载一遍
   → 所以**只能按扩展名**分派。`svg` 有意归到"图片"（文件管理器就该显示成图）。
2. **`/d/*` 是要鉴权头的**，浏览器不给子资源带 `Authorization`，所以 `<img src="/d/...">` 永远不行
   → 一律 `fetchFileResponse()` 取字节转 object URL。**OpenList 的 `/d/*` 是公开的（只有 signCheck），这个项目有意不公开**。
3. **`URL.createObjectURL(await blob)` 是"整份文件进内存才显示"**，`preload="metadata"` 救不了（blob 到元素时已完整）。
   实测真实桶 51 MB 录音半分钟没出来 → `BLOB_SIZE_LIMIT = 16 MB`，超限给说明面板且**不取字节**。
   **用户明确说过这一步下载功能不可用**，所以超限不再退回下载。
4. **懒加载 Monaco 是双赢**：入口包 8,100,278 → 467,387 字节（−94%），Monaco 隔离进 7.6 MB 分块；
   同时让分派器可以在 Node 里 `renderToStaticMarkup`（测试的前提）。
5. **pnpm 会嵌套 React**：`@typefox/monaco-editor-react` 把 React 声明成普通依赖（不是 peer），
   于是在它下面装了 19.2.8（应用 19.2.1），dev server 的依赖预打包把这份内联进去 → 打开文本就 `Invalid hook call`。
   **生产构建是干净的**（Rollup 会去重），只有 dev 会中招。用 `resolve.dedupe: ["react","react-dom"]`。

### 两个真 bug（都不是这一步引入的）

- **Hono 裸 `*` 不是 param**：`app.on(..., "/d/*", ...)` 里 `c.req.param("*")` 是 `null`，路径塌成 `/`，
  **每次下载、以及 `/api/fs/link` 发出去的每个 URL 都 404 "Storage not found"**。必须具名：`/d/:name{.*}`。
  已反向验证过（改回旧写法 → 测试失败）。
- **markdown 渲染器递归时共用全局正则**：内层调用重置 `lastIndex`，外层从同一匹配重启 → 输出无限增长 →
  `RangeError: Invalid string length`。递归前先把匹配物化到 `new RegExp(source, "g")` 的副本上。

## 环境备忘（新增，重要）

- **沙箱的批量删除守卫会挡住 `vite build`**：Vite 清空自己的 `dist/`（gitignored 产物）时被
  `safe-delete-bulk-guard` 拦下，报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`。
  `count`/`threshold` 是 **scope: "turn" 的累计值**（本回合阈值 50，被 vitest/tsc 的临时文件churn 顶穿），
  所以一旦超了，**之后连删 2 个文件的目录也会被拦**。
  **`dangerouslyDisableSandbox: true` 无效**——shim 是 harness 层通过 NODE_OPTIONS 注入的，与沙箱模式无关。
  **可用绕法**：临时在 `vite.config.ts` 加 `build: { emptyOutDir: false }`（跑完必须还原），
  这样不产生任何删除，产物照常生成（入口 467.59 kB、`TextViewer-DKm8sP3.js` 7.6 MB）。
  **不要**去删 guard 的 state dir 或清 `CODEBUDDY_SAFE_DELETE_BULK_*` 环境变量——那是绕过安全控制。
- **`networkidle` 对 Vite dev server 不可靠**：`/waynecos` 是 S3 挂载，出现过一次 **12 秒**停顿，
  `networkidle` 直接超时。改用 `domcontentloaded` + 显式 `waitForSelector('[role="row"]...')`。
  另外 S3 偶尔会**长时间不响应**（25 秒被 AbortController 掐断），这不是代码问题。
- **Monaco 自己会创建 object URL 且不 revoke**：栈里是 `getWorkerBootstrapUrl` /
  `StandaloneWebWorkerService._createWorker`，那是编辑器 worker 的 bootstrap blob，**有意活得比预览久**。
  统计"我们的 object URL 有没有泄漏"时要按栈把它们排除，否则会误报。
- **`addInitScript` 每次导航都会重跑**，页面内的计数器会被最后一次 goto 清零
  → 跨导航累计要写 `sessionStorage`。

## 阶段八 8.4：目录 readme / header（已完成）

### 做了什么

- worker：`metaReadme()` / `metaHeader()` 复刻 OpenList 的 `getReadme()` / `getHeader()`；`fs/list` 带上 `readme`/`header` 字段。
- 前端：`lib/readme.ts`（纯逻辑：选源 + 优先级）、`components/files/DirectoryReadme.tsx`（渲染卡片），
  `FilesPage` 把 header 放在列表上方、readme 放在分页器下方；`MetadataPage` 补上 `header` 与两个 `_sub` 开关。

### 关键事实

- **OpenList 的 Meta 没有 `footer`**，只有 `readme`/`r_sub` 与 `header`/`header_sub` 两对字段
  （`internal/model/meta.go`、`FsListResp` 都是）。清单里说的"三个 md"其实是**每个槽位三个候选文件名**：
  上方 `header.md`/`top.md`/`index.md`，下方 `readme.md`/`footer.md`/`bottom.md`。
- 优先级：**目录里的文件优先于规则**；规则的值可以是 markdown 原文，也可以是 `http(s)` 链接（是链接就抓取）。
- 两个槽位各用自己的 `_sub` 开关，不是共用一个。

### 两个真 bug（都不是这一步引入的，但这一步才暴露出来）

1. **`getNearestMeta` 读错 KV 键**：它读裸键 `"metas"`，而 admin 端点与备份层写的是
   `CONFIG_KEYS.metas` = `"config:metas"`。于是它**永远返回 null → 全应用的元数据规则一直不生效**
   （hide 不隐藏、password 不拦截、`write:false` 不拦写、readme/header 不显示）。
   **为什么以前没测出来**：`meta.test.ts` 的假 KV 是 `{ get: async () => metas }`——**对任何键都返回数据**，
   所以键写错了照样"通过"。教训：**假 KV 必须按 key 应答**，否则测试在验证一个不存在的契约。
   现在 `kvWith()` 只在 `CONFIG_KEYS.metas` 上应答，并加了一条"每次读都必须是规范键"的断言。
2. **`metaCoversPath("/", "/a/b", true)` 返回 `false`**：前缀被拼成 `"//"`。OpenList 的
   `PathAddSeparatorSuffix` 会让 `"/"` 保持 `"/"`，所以根规则在 `_sub` 打开时应当覆盖所有路径。
   这个 bug 让**根规则的 `hide`/`password`/`read_users`/`write_users` 全部静默失效**。
   已反向验证：把修复撤掉 → 恰好两条根路径测试失败。

- 判断"header 在列表上方、readme 在下方"用的是 `compareDocumentPosition`，**不是靠肉眼**。
- 用 `page.route` 注入一个 `readme.md` 列表项并本地供应内容，来验证"文件优先于规则"——**不用往真存储写任何文件**。

## 阶段八 8.5：目录缓存（`caches.default`）

### 做了什么

`src/worker/storage/cache.ts`：按**虚拟路径**做键的目录列表缓存，TTL 取 `cache_expiration`（默认 30 分钟），
`custom_cache_policies`（`pattern:minutes` 一行一条，doublestar glob）覆盖它，`refresh` 同时跳过读**并重写**条目。
`fsList` 改成走 `listDirectory`；所有写路径（mkdir / rename / remove / put / form / copy / move /
remove_empty_directory）按"**持有该条目的那个目录**"失效（不是条目自己）。
恢复了 0.2 移除的 `cache_expiration` / `custom_cache_policies`：registry 公共项重新声明（`noCache` 驱动不声明），
`normalizeStorageConfig` 把它收敛成非负整数（备份里的 `"30"` 要能读，读不出回落 30，负数夹到 0＝不缓存），
`registry.test.ts` 加"表单提供的缓存字段必须被 `storage/cache.ts` 真的读到"的守卫。
另外把 `parentOf` 补进 `worker/storage/types.ts`（前端 `lib/paths.ts` 早有同名函数，两边各一份，worker 不引前端代码）。

### 值得记住的几点

1. **缓存键必须是虚拟路径**：OpenList 的 `Key(storage, path)` 是 `GetFullPath(mount_path, path)`，也就是客户端请求的那个路径。
   若按适配器拿到的相对路径做键，挂载在 `/` 的 `/docs` 与挂载在 `/waynecos` 的 `/docs` 会**撞成同一条**、互相顶掉。
   已用 `envWith(["/", "/waynecos"])` 的集成测试钉死这一点。
2. **空列表要删条目，而不是只"不写"**：OpenList 对空结果走 `deleteDirectoryTree`。只不写的话，
   `refresh` 后发现目录已空时旧条目还在，接下来整个 TTL 都会把删掉的内容又端出来——比不缓存更糟。
3. **`caches.default` 不跨数据中心、无法枚举**，所以失效只在处理写请求的那个 DC 生效。
   因此前端**写之后的重载必须带 `refresh: true`**（新增 `FilesPage.reloadAfterWrite`，工具栏 Refresh 同样带），
   否则"上传成功但列表里没有"会是个真 bug。**TTL 才是陈旧度的真实上界，失效不是。**
4. **`/docs/**` 不匹配 `/docs` 本身**（shell 语义）。第一版单测断言写成匹配，是断言错不是代码错。
   glob 匹配的是**存储内相对路径且带前导斜杠**（`/docs/a`），与 OpenList 传给 `doublestar.Match` 的一致。
5. 接入点**只有 `fsList`**；`fsSearch` / `fsDirs` 仍直连适配器（它们一次走很多目录，把用户从没打开过的目录
   灌进边缘缓存不划算）。
6. `noCache` 分支今天三个驱动都没声明，**没有测试覆盖**，留着是为了下一个驱动。
7. `tsc -b` 的 `-b` 模式与 `vitest` 前台运行在沙箱里都会被 SIGTERM 杀掉（连空输出都没有）。

### 验证方式

- `storage/cache.test.ts` 37 例 + `fs-cache.test.ts` 5 例（真 `S3Adapter` + 打桩 `fetch` + 打桩 `caches`，
  走完整 `app.request`）。合计 **463 例 / 30 文件**。
- **反向验证过守卫会咬人**：临时删掉 `fsMkdir` 的失效调用 → `fs-cache.test.ts` 里"写之后列表必须重新取"立即失败，
  改回即通过。
- 没有做真浏览器 + 真数据验收：`caches.default` 只在真实 Workers（自定义域或 `*.workers.dev`）上可用。
